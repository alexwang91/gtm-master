# Consulting Dashboard Style

This style guide creates a polished English GTM dashboard with a boardroom
consulting feel. It is not affiliated with McKinsey & Company. Use "McKinsey-
style" only as a shorthand for structured, sober, decision-first strategy work.

## Visual Direction

- White or near-white canvas.
- Navy, slate, black, muted blue, and one restrained accent color.
- Dense information with breathing room.
- Strong grid alignment.
- Thin dividers, small labels, and clear hierarchy.
- No decorative gradients, orbs, bokeh, stock-like hero art, or oversized cards.

## Page Structure

1. Title strip: offer, market, date, confidence.
2. Executive answer: one decision, three reasons, two risks, one next action.
3. Market truth: evidence quality and local/category context.
4. Customer and JTBD: target buyer, trigger, job, objection, proof need.
5. Positioning and message: message house, proof ladder, claims to avoid.
6. Pricing and offer: price posture, WTP conclusion, packaging, offer logic.
7. Channel motion: channel priority, owner, budget, expected signal.
8. Launch plan: 30/60/90 day sequence.
9. Evidence and gaps: assumptions, sources, missing data, validation plan.

## Chart Choices

- Use a verdict strip for the top decision.
- Use a driver tree for why the decision holds.
- Use a matrix for segment x channel, claim x proof, or risk x mitigation.
- Use a waterfall for budget or growth contribution.
- Use a funnel for acquisition to conversion.
- Use a range chart for uncertain forecast, WTP, or market size.
- Use a timeline for launch sequence.
- Use an evidence board for source confidence.

Do not use a chart when the data is sparse. Use a table with confidence labels.

## Section Formula

Each section should follow this order:

```text
Answer
Evidence
Implication
Action
Confidence
```

If a section cannot name the action, it is not ready.

## Typography And Layout

- Use compact section headings.
- Use small uppercase labels for metadata.
- Keep paragraphs under four lines.
- Use tables for detail.
- Use callouts for decisions, not decoration.
- Avoid nested cards.
- Keep the first viewport focused on the decision, not a marketing hero.

## HTML Rules

- Produce one self-contained HTML file.
- Use inline CSS and no remote scripts by default.
- Keep charts simple enough to render with HTML/CSS/SVG.
- Escape user-provided text.
- Make the dashboard printable.
- Use accessible contrast and readable font sizes.
